# HOTEL 96 — نسخهٔ ۲.۲

## امکانات نسخهٔ ۲.۲

- نوار سلامتی و گرسنگی و سکه کنار مشخصات بازیکن؛ گرسنگی هر دقیقه کم می‌شود و در گرسنگی صفر، سلامتی آرام‌آرام کم می‌شود.
- حملهٔ بازیکن به بازیکن آنلاین هم‌طبقه با فاصلهٔ زمانی محدود؛ ضربه ۱۲ واحد از سلامتی کم می‌کند.
- تمام مغازه‌ها در طبقهٔ فعلی قابل ورود هستند؛ ورود با صفحهٔ کوتاه بارگذاری و فهرست خرید انجام می‌شود.
- خرید کالا با سکه، کیف وسایل، خوردن غذا برای بازیابی سلامتی و گرسنگی، و پوشیدن لباس.

## امکانات نسخهٔ ۲.۲

- رفت‌وآمد آسانسور به بالا و پایین؛ هر بازیکن فقط تا طبقه‌ای که اول انتخاب کرده می‌تواند بالا برود.
- هر طبقه از منفی ۳ تا ۲۴ یک مغازهٔ تصادفی از ۸ نوع دارد: گوشی‌فروشی، گوشت‌فروشی، حیوانات خانگی، سوپرمارکت، مدرسه، تخم‌فروشی، دست‌دوم‌فروشی و رستوران.
- نوع مغازه‌ها در ذخیرهٔ بازی ثبت می‌شود و با رفرش یا راه‌اندازی دوباره عوض نمی‌شود.
- با خروج بازیکن، نام و طبقه و کلید او تا ۲۴ ساعت رزرو می‌ماند. اگر با همان مرورگر و همان داده‌های سایت برگردد، به همان شخصیت برمی‌گردد.
- ظرفیت ۴ نفر در هر طبقه شامل بازیکنان آنلاین و جایگاه‌های رزروشده است؛ بعد از ۲۴ ساعت جایگاه آزاد می‌شود.
- اطلاعات بازیکنان و مغازه‌ها در PostgreSQL ذخیره می‌شود.
- در هر سه طبقهٔ زیرزمین (منفی ۱ تا منفی ۳) زامبی در راهرو حضور دارد؛ بازیکن می‌تواند از دکمهٔ «فرار» به طبقهٔ بالاتر برگردد.
- امکان دعوت از بازیکن آنلاین همان طبقه به خانهٔ مشترک وجود دارد؛ دعوت‌شونده باید دعوت را قبول کند.
- هفت مینی‌گیم دونفرهٔ آنلاین: فوتبال، پینگ‌پنگ، مسابقه ماشین، مسابقه معما، هدف‌گیری با توپ، بسکتبال و رکوردزنی. هر دور ۴۵ ثانیه است و امتیازها برای هر دو بازیکن به‌صورت زنده نمایش داده می‌شوند.

## خیلی مهم: برای ذخیرهٔ دائمی روی Render باید دیتابیس وصل کنی

اگر `DATABASE_URL` تنظیم نشود، سرور فقط در فایل محلی ذخیره می‌کند. این روش روی کامپیوتر مناسب است، اما فایل‌های محلی سرویس Render ممکن است با راه‌اندازی یا انتشار دوباره از بین بروند. برای ذخیرهٔ دائمی در اینترنت، یک دیتابیس PostgreSQL رایگان/مناسب بساز و آدرس اتصالش را به Render بده.

### ساخت دیتابیس PostgreSQL با Neon

۱. با کمک والدینت وارد <https://neon.tech/> شو و حساب بساز.
۲. یک پروژهٔ PostgreSQL جدید بساز. اگر منطقهٔ Frankfurt در دسترس بود، همان را انتخاب کن؛ وگرنه نزدیک‌ترین منطقهٔ پیشنهادی را انتخاب کن.
۳. در داشبورد Neon بخش اتصال (Connect) را باز کن و آدرس کامل اتصال PostgreSQL را کپی کن. این آدرس محرمانه است؛ آن را در چت یا GitHub منتشر نکن.
۴. در Render داشبورد سرویس `hotel96` را باز کن.
۵. به بخش **Environment** برو و یک متغیر جدید بساز:
   - Key: `DATABASE_URL`
   - Value: آدرس اتصال PostgreSQL که از Neon کپی کردی
۶. ذخیره کن. Render سرویس را دوباره منتشر می‌کند. در شروع اول، جدول ذخیرهٔ بازی خودکار ساخته می‌شود.
۷. بعد از Live شدن، آدرس `https://YOUR-SERVICE.onrender.com/healthz` را باز کن. اگر مقدار `storage` برابر `postgres` بود، دیتابیس وصل شده است.

**هرگز مقدار `DATABASE_URL` را داخل فایل‌های GitHub نگذار.** فقط در Environment Variables خود Render واردش کن.

## انتشار نسخهٔ ۲.۲ روی GitHub و Render

۱. فایل `HOTEL96-V2.1-GitHub-Upload.zip` را استخراج کن.
۲. وارد مخزن قبلی `HOTEL-96` در GitHub شو.
۳. از **Add file → Upload files** استفاده کن.
۴. محتویات استخراج‌شده را با همان ساختار پوشه‌ها آپلود کن و فایل‌های هم‌نام نسخهٔ قبلی را جایگزین کن. پوشهٔ `public` باید در ریشهٔ مخزن باشد و داخلش `index.html`، `game.js` و `style.css` قرار بگیرند.
۵. پایین صفحه **Commit changes** را بزن. Render در صورت فعال بودن اتصال خودکار، نسخهٔ جدید را Deploy می‌کند.
۶. اگر Render خودکار Deploy نکرد، در داشبورد سرویس روی **Manual Deploy → Deploy latest commit** بزن.
۷. قبل یا بعد از Deploy، متغیر `DATABASE_URL` را طبق راهنمای بالا تنظیم کن.

## اجرای محلی

- Node.js نسخهٔ ۱۸ یا بالاتر لازم است.
- در ویندوز `START-HOTEL96.bat` را اجرا کن.
- برای ذخیرهٔ محلی، سرور به‌صورت خودکار فایل `data/hotel-state.json` را می‌سازد.
- برای دیتابیس محلی یا آنلاین، متغیر محیطی `DATABASE_URL` را تنظیم کن.
